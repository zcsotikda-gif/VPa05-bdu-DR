# Напоминалка для macOS

Десктопное приложение-напоминалка: хранит напоминания в SQLite и показывает их
в срок — системным баннером macOS и окном поверх всех окон. Уведомления
приходят и при свёрнутом окне.

## Что умеет

- добавить напоминание: заголовок, описание, дата и время;
- удалить напоминание;
- отметить «Готово» или «Отменено»;
- быстрое действие **«Отложить на 30 мин»** — переносит срок и возвращает
  напоминание в «Ожидает», чтобы оно прозвенело снова;
- сам переводит наступившие и пропущенные напоминания в «Просрочено»;
- показывает список с фильтром по статусу: «Все», «Ожидает», «Готово»,
  «Просрочено», «Отменено».

Статусы — не украшение: «Готово» и «Отменено» конечные, планировщик их не
трогает и повторно не звонит, а запись остаётся в истории (в отличие от
удаления).

## Как показывается напоминание

Два способа работают вместе, и это не дубль:

- **системный баннер** через встроенный `osascript` — попадает в Центр
  уведомлений, виден в истории. Отправителем macOS покажет Script Editor:
  собственное имя и значок потребовали бы либо сторонней утилиты, либо сборки
  настоящего `.app`;
- **окно поверх всех окон** — с кнопками «Готово», «Отменить», «Отложить
  на 30 мин».

Звук только у баннера, и это негромкий системный `Purr`; окно открывается молча.
Системный сигнал тревоги (`window.bell()`, звуки вроде `Ping` и `Sosumi`) не
используется намеренно — для напоминания он слишком резкий. Звук меняется
параметром `DEFAULT_SOUND` в `src/reminder/notifications/banner.py`; доступные
имена — файлы из `/System/Library/Sounds`.

Окно нужно потому, что `osascript` сообщает «отправлено», а не «увидено»: при
включённом «Не беспокоить» или отключённых уведомлениях баннер не покажется и
об этом не сообщит. Окно от настроек системы не зависит.

## Требования

- macOS;
- Python 3.12 из Homebrew;
- `tkinter` — через pip он не ставится, нужна формула Homebrew.

## Установка и запуск

```sh
brew install python-tk@3.12

cd <каталог проекта>
/opt/homebrew/opt/python@3.12/bin/python3.12 -m venv .venv
.venv/bin/pip install -e ".[dev]"

.venv/bin/python -m reminder
```

Проверить, что Tk на месте:

```sh
.venv/bin/python -c "import tkinter; print(tkinter.TkVersion)"
```

Файл базы по умолчанию — `reminders.db` в текущем каталоге. Другой путь задаётся
переменной среды `REMINDER_DB`. В `~/Library` ничего не создаётся намеренно:
проект не оставляет следов вне своего каталога.

## Тесты

Безэкранная часть (хранилище, правила, планировщик, уведомители) проверяется
в Linux-контейнере — там нет Tk, и это намеренно: если зависимость от `tkinter`
просочится в ядро, тесты упадут.

Нужен запущенный Docker Desktop. Отдельно собирать образ не требуется — первый
же запуск соберёт `reminder-tests` сам:

```sh
docker compose -f docker/compose.yaml run --rm tests
```

Флаг `--rm` удаляет контейнер после прогона, поэтому в Docker Desktop остаётся
только образ `reminder-tests`. Чтобы контейнер `reminder-tests-1` остался в
списке в состоянии `Exited`, запуск без удаления:

```sh
docker compose -f docker/compose.yaml up --abort-on-container-exit tests
```

Пересборка нужна не всегда: `src/` и `tests/` смонтированы в контейнер, поэтому
правки кода видны сразу. Собирать заново надо после изменения `pyproject.toml`
(например, появилась зависимость) или `docker/Dockerfile`:

```sh
docker compose -f docker/compose.yaml build
```

Убрать за собой — контейнер и образ одной командой:

```sh
docker compose -f docker/compose.yaml down --rmi local
```

После такой уборки следующий запуск соберёт образ заново, ничего настраивать
не нужно.

То же локально:

```sh
.venv/bin/pytest
.venv/bin/ruff check src tests
```

Окно и баннер в контейнере не проверяются: из Linux их взять негде.

## Структура

```
main — точка входа: src/reminder/__main__.py (единственное место сборки зависимостей)

src/reminder/
├── ports.py              протоколы Storage и Notifier — то, что нужно ядру от мира
├── domain/
│   ├── models.py         Status, Reminder и действия: Notify, ChangeStatus, Reschedule
│   └── rules.py          decide() и snooze() — чистые функции, вся предметная логика
├── storage/
│   ├── schema.sql        таблица reminders с CHECK на статус
│   └── sqlite.py         чтение и запись; решений предметной области нет
├── notifications/
│   ├── banner.py         баннер macOS через osascript
│   ├── popup.py          очередь для фонового потока + показ окна
│   └── composite.py      несколько уведомителей как один
├── scheduler.py          поток-демон: взять ожидающие, спросить правила, исполнить
├── ui/app.py             окно: список, фильтр, кнопки
├── clock.py              UTC внутри, местное время человеку
└── config.py             путь к базе
```

Зависимости направлены внутрь: `domain`, `storage`, `scheduler` и `ports` не
знают ни про `tkinter`, ни про окно. Правило «что считать просроченным» живёт
в `domain/rules.py`, а не в SQL-запросе и не в планировщике — поэтому его можно
прочитать и проверить, не поднимая ни базу, ни экран.

Время хранится в UTC в формате ISO-8601 (сортируется как строка и не плывёт при
переходе на зимнее время); человеку показывается местное.
